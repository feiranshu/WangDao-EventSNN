## 当前第一阶段：实施状态与验收协议

本阶段允许重构 ANN/CNN；H2 是全 ANN，旧 S1 是 SNN 前端加 ANN 后端，新 C0—C4 均为因果 ANN 原型，不提前称为 SNN。先提高事件级 micro IoU，再在精度基本保持的条件下降低完整链路开销；本阶段不继续 LOA/PoT、官方模型 Test 复测或 RTL。

### 依据与可检验假设

历史 Validation：H2/S1 IoU 为 86.1630%/83.6273%；S1 相对浮点 S0-P 仅下降约 0.06 个百分点。S1 的 7,671 个漏检中 6,335 个（82.6%）已通过候选门控，候选比例43.02%却高于定点H2的31.95%。Refiner 的32维输入有4维来自 Proposal 上下文。因此先验证后端分布适配，不直接用增加候选量掩盖后端错误。这些是旧离线结果提供的线索，不能算新因果模型增益。

核心假设：共享短/长历史证据有助于弱目标检出，而强 Refiner 集中处理困难事件可能降低平均成本。共享卷积、递归记忆、路由均不是单独的“革命性”创新；研究贡献须由统一评测和消融支持。

### 模型与因果契约

- 时刻 t 发布 `[t-25,t)` 内事件；只用截止t已到达的事件，边界t事件进入下块。每个事件保留唯一索引并恰好输出一次；序列开始重置，跨块保留状态。允许25ms内等待，必须计入端到端时延。
- 表征用真实滚动25/50/100ms正负计数（6通道）和正负最近活动时间（2通道）；不使用整段序列终点归一化。官方定位50ms开区间与整数毫秒处理独立保持。
- C0：因果32维统计，保留两级MLP；C1：4像素网格、3×3卷积24/32通道，第二层降到8像素网格，再接两个局部残差块，事件拼接32维共享特征。
- C2：低分辨率32通道的1/2和7/8双衰减状态，拼接经1×1融合；衰减不等价于输入计数的50/100ms精确窗口。
- C3：64→128→64→4强Refiner处理所有候选；C4：64→32→4轻头，置信不确定、稀疏或前块冲突事件进入强头。4输出是二分类每类两个prototype，不是4个语义类别。
- B1/B2仍属旧100ms离线机制实验，其方法有效后才迁移到因果流程。C0—C4输入和状态为新格式，不能加载旧S1权重并假定数值等价。

## 1. 项目目标与边界

本项目面向 EV-UAV 事件流小目标检测，研究真实时序 SNN、低位宽定点、PoT 和近似加法对精度与硬件成本的影响，并在 FPGA 上完成可复现的最小系统闭环。

最终需要回答四个问题：

1. SNN Proposal 相比 H2 ANN Proposal 能否保持可接受精度并减少事件驱动突触运算。
2. 定点、PoT 和近似加法分别造成多少精度损失，能带来什么硬件收益。
3. Python 黄金模型、RTL 仿真、综合和 FPGA 板级输出能否逐级对齐。
4. 在同一器件、时钟和数据条件下，exact 与 approximate 模式的资源、时序、延迟和功耗有何差异。

项目不要求机械照搬立项书。技术路线可以根据证据调整，但必须保留统一数据划分、阶段冻结、不以Test调参与逐级验证。

原始申请书见 `../project_proposal/Feiran_Shu-24307140011-personal_innovation_design_report.pdf`。申请书提出了自适应时间切片、阈值注意力、PoT 无乘法器、LOA、动态 exact/approx 切换、AER、局部缓存和 FPGA 闭环。当前路线保留 SNN、定点、近似计算和 FPGA 四项核心目标；其余内容按证据与进度列为后续扩展。申请书中的计划性表述和不可复现前期结果不作为当前完成证据。

## 3. 系统结构

### 3.1 软件模型

```text
346×260 EV-UAV 事件流
  → 每条 8 s 序列分为 80 个 100 ms 窗口
  → 每个窗口切分为 T=4 个微时间片
  → 每窗 336 个重叠 patch，每个 patch 生成 128 维 uint8 特征
  → S1-P Proposal-SNN：128→48→24→16
  → 候选事件路由
  → A1-H2 ANN Refiner：32→64→32→4
  → 事件分类、连通域和目标定位
```

Proposal-SNN 的神经元具有跨微时间片膜电位状态；不同窗口和不同 batch 之间不共享状态。Refiner 保持 ANN，是当前精度与硬件复杂度之间更可靠的折中。

### 3.2 FPGA 第一版

```text
PS：读取事件与生成 patch 特征
  → 内存或 DMA
PL：定点 Proposal-SNN 核心层
  → PS：候选路由、ANN Refiner、后处理和显示
```

第一版不以原始 AER 直连、自适应时间窗、3×3 异步缓存或完整复杂检测网络上板为前置条件。先完成可验证的 PS→PL→PS 闭环，再决定是否扩展事件相机直连。

### 4.4 EV-UAV 论文口径与 STC 实验

- 论文、WSL 官方模型复现和当前 Validation 的指标定义、阈值及限制已经归档到 `results/evuav_metric_alignment.json`。论文 ACC 对应目标事件 Recall；Fa 表格值是原始小数乘 `10^4`。

- 冻结 S0-P 在完整 10 条 Train-dev 上完成 STC 诊断，未训练模型，也未使用 Validation/Test。三个候选邻域均通过预设门槛。

## 5. 已完成：S0-P STC 受限实验

### 5.1 已实现协议

- `ProposalSNN.forward_temporal()` 在不改变默认 `forward()`、冻结权重和定点接口的前提下，返回四个 25 ms 微时间步的输出电流。
- 训练标签构造成 `[窗口, 时间步, 336 patch, 16 cell]`，重叠 patch 用可微最大值融合为 34×44 时空热图；其时间聚合与现有 NumPy 映射逐元素一致。
- `proposal_stc_loss()` 使用公开代码的邻域概率和、全局均值中心化、sigmoid 和权重断梯度规则。论文公式的 `γ=2` 与公开实现差异在诊断结果中分开记录。
- 每个训练核心块含四个连续 100 ms 窗口，前后各一个 halo。Focal、Dice 和蒸馏仍使用 POS15 采样的核心 patch；STC 使用完整连续块；核心窗口不会重复计入损失。
- 四个候选 `λ_STC=0/0.05/0.10/0.20` 共享初始化、序列顺序和采样索引，固定 T4、POS15、KD50、seed42、20 epochs。训练过程只写入一个 `results/runs/S0P-STC-T4-S42/` 目录。
- 训练默认后台预取下一条 Train-main 序列，并跨 epoch 缓存 10 条固定 Train-dev 表征；两者都不改变训练顺序、采样或数值路径。逐轮记录数据等待比例、缓存命中和缓存占用，用于识别 CPU 瓶颈。
- `λ_STC=0` 的单步参数更新与原损失路径完全一致。新连续块组织是否造成整体退化，由正式 Train-dev 的 λ=0 对照门槛判断。
- 训练结束后，`select_stc.py` 只在 Train-dev 用固定 Proposal 阈值 0.51 端到端评测基线和四个候选；训练损失不能直接决定最终候选。

## 6. 已完成：S3 近似加法

### 6.1 目标

在不训练、不使用 Test、不叠加 PoT 的前提下，为 S1 建立可综合、可逐位复现的近似加法黄金模型，判断哪些运算位置和近似低位数能通过精度门槛。首轮结束后必须得到明确的正面配置或负面结论。

S3 只修改 Proposal-SNN。A1-H2 Refiner、数据表征、候选阈值、事件阈值和后处理全部保持 S1 不变。

### 6.2 首轮加法器协议

首轮采用 24 位有符号二进制补码 LOA。`k` 表示近似低位数，扫描 `k ∈ {2, 4, 6, 8}`；`k=0` 是 exact 对齐基准。

对两个已经限制在 24 位有符号范围内的操作数 `a`、`b`：

1. 低 `k` 位输出为两个操作数对应位的按位或。
2. 进入第 `k` 位精确高位区的进位，为两个操作数第 `k-1` 位的按位与。
3. 第 `k` 位及以上执行精确加法。
4. 结果按 S1 的 24 位有符号范围饱和，并累计饱和次数。

线性层采用固定平衡加法树：输入通道按索引升序排列，每层从左到右两两配对，奇数个操作数时最后一个直接传到下一层，直到得到一个结果。每个树节点都使用同一 24 位加法协议。该顺序必须与未来 RTL 一致，因为近似加法不满足结合律。

膜电位近似只替换 `leaked + current`。泄漏乘法与舍入、阈值比较、软复位、读出求平均和概率后处理继续使用 S1 精确规则。

### 6.3 实施顺序

#### A. 位级实现与测试

在 `software/wangdao/fixed.py` 中加入独立的 LOA 运算、固定加法树和统计接口，在 `software/tests/test_snn.py` 中覆盖：

- 正数、负数、零、符号边界和饱和边界；
- `k=0` 与 S1 精确加法一致；
- 手工可验证的 `k=2/4/6/8` 位模式；
- 固定树顺序不随数组布局或分块改变；
- 空 batch、错误位宽和错误 `k` 能给出明确错误。

当前实现已完成：NumPy 版本作为软件黄金模型，PyTorch 整数后端在 CPU/CUDA 上执行相同的二补码、固定树和逐节点饱和规则。自动测试覆盖两种后端逐位一致性。CUDA 只用于缩短扫描时间，不改变模型或选择口径。

#### B. exact 回归

先用 `k=0` 跑小样本和 HW-calibration。必须与 S1 的 logits、候选、事件输出和全部指标一致；如不一致，停止近似扫描并修正运算顺序或位宽契约。

随机输入测试、扫描期间的分层抽样及独立全量 HW-calibration 对齐均已通过。独立全量检查以 `syn_all+mem_all, k=0` 覆盖 10 条序列和 4,300,800 个 logits，输出、发放和饱和统计全部与 S1 一致，证据保存在 `results/approx_exact_alignment.json`。

#### C. HW-calibration 单因素扫描

新增 `software/scripts/evaluate_approx.py`，以同一次数据读取比较 S1 和全部候选。先分别扫描，首轮不得同时近似突触累加和膜电位更新：

| 扫描组 | 近似位置 | 其他位置 |
|---|---|---|
| `syn_l1`、`syn_l2`、`syn_l3` | 单个线性层的加法树 | exact |
| `syn_all` | 三个线性层的加法树 | exact |
| `mem_l1`、`mem_l2` | 单个隐藏层的 `leaked + current` | exact |
| `mem_readout` | 无脉冲读出膜更新 | exact |
| `mem_all` | 两个隐藏层和无脉冲读出的全部推理膜更新 | exact |

每组扫描 `k=2/4/6/8`，记录 Event IoU、F1、Precision、Recall、Pd、Fa、Proposal Recall、候选比例、逐层发放率、近似加法次数、exact/approx 输出差异和饱和次数。结果集中写入 `results/approx_calibration.json`，不为每个候选新建文件。

`FixedSNN` 中用于统计输出发放率的 `spike_membrane` 不参与检测 logits，也不进入首版 FPGA 推理数据通路，因此只保留 exact 统计，不能作为 S3 候选收益。

候选进入下一步必须同时满足：

- HW-calibration Event IoU 相对 S1 下降不超过 1.5 个百分点；
- Proposal Recall 相对 S1 下降不超过 1.0 个百分点；
- 候选比例相对 S1 增加不超过 10 个百分点；
- 不出现 S1 中不存在的累加器或膜电位饱和；
- 至少覆盖一个会在 RTL 中真实替换的加法位置，而不是只改变软件后处理。

在通过门槛的候选中，先最大化被近似的加法次数，再最小化 IoU 损失；若两者冲突明显，保留 Pareto 前沿并在 JSON 中给出选择理由。

#### D. 组合与冻结

只有单位置或单组候选通过后，才允许组合近似位置。组合仍只在 HW-calibration 选择一次配置，不引入训练。冻结内容包括：

- S1 基础权重及其哈希；
- LOA 位宽、`k` 和插入位置；
- 加法树顺序、饱和、泄漏和复位规则；
- Proposal 阈值、事件阈值和后处理版本。

冻结后新增 `software/scripts/evaluate_s3.py`，在 Validation 只运行一次，写入 `results/s3_validation.json`。Validation 相对 S1 下降仍不得超过 1.5 个百分点。若失败，S3 作为负面消融归档，S1 exact 继续作为 FPGA 主线。

首轮不进行误差感知训练。只有全部结构候选均失败且仍有明确研究价值时，才另行规划微调；预计超过五分钟的训练必须先交给用户执行。

### 6.4 最终结果

- 单因素扫描覆盖 8 组位置与 `k=2/4/6/8` 共 32 个候选，22 个通过门槛；优先单因素候选为 `syn_l1_k4`。
- 唯一组合扫描比较 8 个受限候选，冻结 `syn13_memall_k2`。HW-calibration Event IoU 为 75.3689%，相对 S1 下降 0.4688 个百分点，零饱和。
- Validation 上 S1/S3 Event IoU 为 83.6273%/83.2342%，S3 下降 0.3931 个百分点；F1 为 91.0838%/90.8501%，Proposal Recall 为 97.9605%/98.4429%，Pd 为 85.9811%/85.9182%，全部零饱和。
- S3 在 24 条 Validation 上执行 16,907,304,960 次近似加法，覆盖当前 Proposal 目标加法位置的 85.31%。该计数是硬件研究代理，实际面积、时序和功耗必须由同一 FPGA 上的综合与板级测试确认。
- 正式证据分别保存在 `results/approx_exact_alignment.json`、`results/approx_calibration.json`、`results/approx_combination.json` 和 `results/s3_validation.json`；Test 未使用。

| 风险 | 触发信号 | 处理方式 |
