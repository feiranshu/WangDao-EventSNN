# S2 运算与状态账目口径

研究 ANN 与 SNN 的 Refiner 连接数均为 `36×48 + 48×32 + 32×4 = 3,392`，故结构稠密账目为每候选事件 3,392 MAC。冻结 Proposal 另计每完整 100 ms 窗口 2,580,480 稠密 MAC，不把它归入 Refiner 节省。研究 ANN Refiner 有 3,392 个权重；SNN 另有四原型轨迹增益、残余电位增益与 bias 共 12 个读出参数。

| 项目 | S2 定义 |
| --- | --- |
| ANN 跳零有效 MAC | 对每层分别用非零输入/隐藏激活数乘输出宽度。仅是规定跳零假设下的算法计数；PyTorch 实际仍执行稠密矩阵乘法。 |
| SNN 多值输入 MAC | 非零的 36 维 `uint8` 特征分量数 ×48。输入按 FP32 归一化后仍为多值，不能算二值 AC。 |
| SNN 二值 AC | 第一层发放数 ×32，加第二层发放数 ×4。第三层发放进入轨迹更新，不再经过下一层矩阵。 |
| 状态与读出标量操作 | 有正时间差的访问 ×88 个衰减乘法；每候选 84 个阈值比较；每候选 8 个轨迹/电位读出乘法。reset、指数函数、soft reset、max/softmax、地址计算等另有成本，当前未完整计量。 |
| 逻辑状态访问 | 每候选更新 48+32+4 个膜电位及 4 个轨迹，记 88 通道读、88 通道写。它描述数学状态更新，不代表已实测的 CPU 内存总线读写；分桶实现可改变物理访存。 |
| 常驻状态 | 87×65 个有效单元 ×88 通道 ×4 B = 1,990,560 B；每单元 FP64 最后访问时间再加 45,240 B，合计 2,035,800 B。另有冻结 Proposal 热图历史 11,968 B；事件缓存、候选元数据与训练缓存另列。 |
| 实际耗时 | `train.py` 报 Train-dev 缓存后 Refiner 回放的 CPU wall time；不含完整冻结 Proposal 的在线特征构建、窗口采集等待及队列延迟。 |

完整 B04 整网有效 MAC 尚不能由当前 Refiner 账目求出，因为本轮没有重测冻结 Proposal 的有效 MAC。也不能从运算数推断硬件能耗或 KV260 延迟。闭合窗口输出的观察等待至少到窗口右边界，不能称为 10 ms 逐事件发布。
