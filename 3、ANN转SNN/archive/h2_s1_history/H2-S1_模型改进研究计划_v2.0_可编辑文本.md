# 03 / 审阅结论与路线调整

01 / EXECUTIVE REVIEW

原计划有研究价值，但不能直接保证“超过当前H2且更简单”。主要缺口是比较对象、减层实验和最终测试验收没有围绕你的目标形成闭环。

| 原计划的偏差 | 新版处理 |
| --- | --- |
| 主门槛是相对C0提升1至2点；C0可能低于H2 | 主线必须同时比较冻结H2与公平调阈值后的H2。 |
| B1适配S1候选；改善S1不等于超过H2 | 新增H2自身后端适配；S1分支降为条件性迁移。 |
| CNN、双记忆、强弱双头逐步加复杂度 | 先训练与特征诊断；明确删除隐藏层及学生蒸馏对照。 |
| 25 ms因果化与结构研究同时改变信息条件 | 先固定H2信息范围；在线化另立基线和结论。 |
| 本阶段不读Test，无法直接回答测试目标 | 冻结后一次旧Test复测；独立泛化另用封存数据。 |

## 当前H2证据：只能提供线索，不能预报新模型成绩

历史Validation：事件IoU 86.1630%，Recall 91.0772%，Precision 94.1070%，F1 92.5673%。Overall Accuracy虽为99.3273%，但背景占95.40%，不适合作为唯一主目标。

历史Validation的门控/后端漏检为699/5,146，仅作线索。现已完成10条Train-dev诊断：总FN 4,421，其中Proposal 478、Refiner 3,943（89.19%）。因此先验证A1后端适配。

H2是ANN；导出路径使用int8权重、uint8激活及缩放规则。H2、定点A1-H2、S1和新浮点重建版本须分开记录。当前软件回归82项通过；本地冒烟不代表正式训练收益。

# 04 / 把“明显提升”写成可验证门槛

02 / SUCCESS CRITERIA

## 三类模型必须同时保留

| 模型 | 用途与工作点 |
| --- | --- |
| H2-F：原始冻结版本 | 权重不变，Proposal约0.51、事件阈值约0.28；回答相对当前系统改善多少。 |
| H2-R：公平选点版本 | 同一冻结权重，在Train-dev按共同网格选阈值；隔离仅靠调阈值得到的收益。 |
| A* / S*：精度最优 / 简化候选 | 所有配置只由Train-dev决定；若无简化候选合格，则交付A*。 |

## 建议预先登记的验收目标

| 维度 | 通过条件（研究目标，不是保证） |
| --- | --- |
| 主精度 | 在同一评测集、同一信息协议下，A*相对H2-R及H2-F的micro IoU均提升至少1.0个百分点；争取2.0点。 |
| 不以漏检换虚警 | 相对H2-R，Recall与Pd各下降不超过0.5个百分点，Fa增加不超过10%；Fa为0时要求候选也为0。 |
| 稳定性 | Train-dev三种子配对增益均为正；正式报告效应量和按独立采集组配对bootstrap的95%区间。 |
| 可信提升 | 预先指定主比较的IoU差值95%区间下界大于0，且达到1.0点实际门槛；样本不足或区间跨0则写“证据不足”。 |
| 结构简化 | S*先满足上述精度门槛，且比A*最多损失0.3点；目标至少删除一个串行可训练层、整网权重减少20%。 |

1个百分点是绝对差值：例如86.16%到87.16%。这只是说明门槛，不能把历史Validation的86.1630%作为Test的起始分数。

## 指标与选择规则

主指标micro IoU=ΣTP/(ΣTP+ΣFP+ΣFN)。补充Precision、Recall、F1、事件AP、逐序列IoU和官方50 ms定位Pd/Fa。ACC_official=Recall，事件AP不是框检测mAP。

精度明显更优但更复杂：可交付A*，注明简化目标未达成。只变小但未超过H2：仅算压缩结果。不能用加权总分让复杂度抵消精度退化。

| 新封存评测集 | 待落实 | 按独立采集组建立并封存；开发者不看标签或中间成绩。 |

## 先检查独立性，再相信置信区间

1. 审计原始录像/采集场景/时间段/目标轨迹是否跨集合；优先用元数据与重复哈希，不为审阅读取Test标签。哈希相同可证明重复，哈希不同不能证明独立。
2. 不能把同一录像的邻近切片随机分入训练和测试。保留官方划分；若查出重叠，披露限制并另建独立评测，不能静默重划。
3. 新增数据提前约定场景、目标尺度、运动、照明和负样本比例；以24至40个独立采集组作为资源规划起点，样本量充分性仍需按预期效应和开发集组间差异评估。
4. 若六周内无新数据，仍完成一次旧Test同协议复测，但结论必须限于“已公开基准上的改进”，独立泛化验收保持待完成。

## 小开发集的稳健性检查

对入围方案做逐组收益和留一组敏感性分析；如拟合阈值，留出组不得参与该轮选点。此检查不等于重新训练的交叉验证。分组规则在看候选收益前确定，不按最差Test场景选结构。

区间计算以独立采集组为重采样单位，基线与候选使用相同抽样组；每次重算汇总TP/FP/FN的IoU差。没有组信息时只能以序列近似并注明局限，不能把百万相关事件当百万独立样本。

数据角色保护和三种子冻结入口已实现；Validation/Test尚未运行。只有冻结后才能按README_SERVER.md的阶段门执行，不能绕过保护直接改角色名。

# 06 / 步骤1 亲手定位H2的错误来源

04 / ERROR ANALYSIS

## 研究问题与知识重点

H2剩余误差主要来自候选漏检、后端判别、数值重建、输入表征还是工作点？掌握级联条件概率、混淆矩阵、类不平衡与错误归因；先从H2本身出发，再看S1迁移。

## 你亲手完成的代码与分析

1. 选一条Train-dev序列，保留原事件索引、候选掩码、连续分数和标签，独立统计门控FN、后端FN、FP、TP、TN。标签只能在训练/评分侧使用。
2. 手算并验证Recall最终=候选目标召回×后端条件召回。用5至10个人工事件覆盖候选外正样本、重复时间戳、排序及回填。
3. 扩展到全部10条Train-dev；绘制PR曲线、逐序列增益表，按预先定义的稀疏、密集背景、快速位移及边界分组。
4. 分别做“真实解除门控的全事件分类”和“只在相同候选上替换上下文”诊断。理想标签/理想门控只用于估计误差空间，不作为可部署方案。
5. 从Train-dev提取至少3个失败和2个成功时间片，解释分数与局部事件结构；核对H2的28维基础特征加4维上下文。

## 必须通过的检查

| 检查 | 正确结果 |
| --- | --- |
| 事件计数与索引 | TP+FP+FN+TN等于全事件；候选外目标计入FN；每个事件恰好输出一次。 |
| 全事件分类诊断 | 真正运行所有事件的分类头并读取未乘门控的概率；不能用未计算事件的零logit代替。 |
| 数值与冻结权重 | 复现原H2输出；浮点重建差异单列，不能视作训练增益。 |

## 阅读、交付与阶段决定

精读[R1]任务与指标；按需查[R2]表示方法；对照[R6]同任务相关工作。交付错误分解表、失败案例、两个可证伪假设和一页研究笔记。

进入下一步的条件：你能说明每个候选改动试图减少哪类错误，以及什么结果会否定它。若错误统计不守恒或重建不一致，先修复再训练。

# 07 / 步骤2 优先做不加层的H2改进

05 / LOW-COST ACCURACY

## 研究问题

在保持H2结构、信息范围和推理流程不变时，重新适配训练分布能否提高识别精度？本步骤从H2候选出发，不直接套用固定S1前端的B1脚本。

| 编号 | 只改变什么 | 对照与退出条件 |
| --- | --- | --- |
| A0 数值重建 | 建立可训练H2后端，初始权重来自H2 | 先比较原导出、浮点重建、训练后结果；数值差异不得混入增益。 |
| A1 H2后端适配 | 冻结H2 Proposal；在真实候选上微调原Refiner | 首轮保持原损失；比较H2-F、H2-R与A0。 |
| A2 训练分布修正 | 保留全部正样本，并混合困难与随机负样本 | 相对A1单变量比较；检查负样本确实被截断及完整事件指标。 |
| G 门控诊断 | 只扫描Proposal工作点，分类头权重不变 | 仅当前端漏检明显限制精度时启用；同时报告候选率与全链路成本。 |

## 你亲手实现与调试

1. 复核候选缓存的前端权重、数据角色、原始索引和特征版本；训练候选必须由冻结H2产生。
2. 检查一次前向、反向、损失和参数更新；打印正负样本各自损失/梯度贡献，确认没有重复归一化或空batch除零。
3. A1先用原Refiner损失作基准；不要同时加入新损失、增强与蒸馏。A2若改变采样，写清采样概率及是否使用权重校正。
4. 困难样本只能从Train-main挖掘，保留随机负样本防止只学特殊噪声；训练后在全部Train-dev事件上评分。

## 训练与结论边界

首轮seed42、最多20轮；微调初始学习率1e-4，按同一早停/阈值协议比较。若训练曲线未收敛，只可在预留预算内对主要对照与候选一起延长；不能只给新模型更多机会。

读取[R3] Focal Loss与[R4] AdamW，解释“训练侧改动如何影响FP/FN，但不能自动找回被拒绝的目标”。S1-B1只有需要后续迁移时再做，不占主线首批预算。

交付A1/A2全dev结果、训练诊断和数值差异表。仅调阈值有收益时，承认为工作点改进；两次有依据的尝试仍无增益，就停止该分支。

# 09 / 步骤4 显式减层，再验证蒸馏

07 / SHALLOW STUDENTS

## 目标与计数口径

H2 Proposal为128→48→24→16，Refiner为32→64→32→4，共6个串行权重层、11,904个权重元素。先减少高频Refiner层数，避免用双头路由代替真正的结构简化。

| 候选 | 结构与理论权重数 | 研究目的 |
| --- | --- | --- |
| S-R1 | Proposal不变；Refiner 32→32→4。合计8,832，减少25.8%；6层变5层。 | 首选减层候选；保留原4输出语义。 |
| S-R2 | Proposal不变；Refiner 32→64→4。合计9,984，减少16.1%；6层变5层。 | S-R1精度不足时放宽宽度；不满足20%权重目标也应如实报告。 |
| S-P（后续） | Proposal 128→48→16，配S-R1时合计8,064，减少32.3%；共4层。 | 仅在Refiner减层已通过时再试；门控召回需重新验证。 |
| 单级探索（不默认跑） | 移除Proposal时须重构28维基础输入，去掉4维依赖上下文。 | 全事件推理可能更慢；不是删除模块即可等价。 |

以上是不含bias、缩放及其他状态的结构计算，且假定仍为原32维输入；新增特征后必须重新计算。理论降幅不是实测速度或功耗。

## 你亲手完成的蒸馏实验

1. 先训练S-R1的无蒸馏版本S0，再训练相同初始化/预算的蒸馏版本S-KD；教师固定为已经验证更好的A*。
2. 沿用二分类、每类两个prototype的聚合规则，先聚合成二类logit再蒸馏；4输出不是4种目标类别。
3. 首版只做logit蒸馏：L=L任务+λT²·KL(p教师,T || p学生,T)。以T=2、λ=0.2作为待验证起点，限制调参预算。
4. 检查教师无梯度、KL方向、温度缩放和事件对齐；主对照共享冻结Proposal与候选集。老师在候选外的零分数不可直接当真实软标签。

## 阅读、交付与决策

精读[R5]蒸馏。交付S0/S-KD/A*同条件表；蒸馏失败时优先保留直接训练学生。若A*本身采用不同结构或信息范围，必须单列迁移损失与差异。

S*必须仍超过H2，并在A*的0.3个百分点容差内。若减层伤害主要目标，保留A*并明确简化目标未达成，不为层数好看牺牲准确性。

08 / OPTIONAL CAUSAL TRACK

25 ms在线发布有工程价值，但它不是本次“准确性优先”的默认前置条件。原C0-C4路线保留；仅当主精度结论稳定、预算充足或确有在线需求时进入。

| 旧路线 | 新版定位与门槛 |
| --- | --- |
| C0 因果MLP | 建立独立25 ms信息契约；量化相对H2离线流程的代价，不能混称同条件结构比较。 |

## 你必须掌握的因果契约与测试

1. 时刻t发布[t-25,t)内事件，恰好t的事件进入下一块；只读取截止时间之前的x/y/t/p。记录同块等待时间，不能称为零延迟逐事件预测。

3. 25/50/100 ms计数与EMA是不同机制；8块TBPTT仅截断梯度，不自动清除超过200 ms的历史。
4. 若做C4，区分轻错强对与轻对强错，检查输出影响后续状态的闭环。路由不确定区域应围绕实际工作点，而不是默认0.5。

# 11 / 步骤6 统一选点与修正实现缺口

09 / FAIR COMPARISON

## 所有模型使用同一选择流程

## 什么算一种配置

## 先估算成本，再启动完整训练

先在短配置测每轮训练和完整dev评测时间、CPU等待与显存；用“配置数×种子数×每轮时间×轮数”估算基础开销，再加评测/失败重试余量。至少预留30%的总GPU时间给关键对照、多种子和最终复测，不能全部花在新结构上。

## 分支停止规则

1. 连续两次有证据指导的受控尝试仍无稳定dev收益，停止该分支；新增尝试要占名额。
2. 候选初筛平均增益不足0.3个百分点或跨种子反复变号，不优先压缩或扩展；这只是开发筛选，不替代最终1点门槛。
3. 第4周仍无可信精度提升：暂停压缩、在线化与量化，集中核查数据、训练及特征；报告阶段目标未达成。
4. 简化候选损失超过0.3点，或失去相对H2的明显提升，保留A*。减少参数但整体变慢时不得宣称加速。

# 14 / 层数、复杂度与实际速度分别验证

12 / COMPLEXITY AND MEASUREMENT

## 先明确“更简单”具体指什么

| 维度 | 记录与判断 |
| --- | --- |
| 网络深度 | 统计Proposal与Refiner最长串行路径上的Linear/Conv层；同时列分支数、阶段数与递归状态，不能只数分类头。 |
| 权重与存储 | H2矩阵权重11,904；另列bias、缩放、数据类型、导出文件与工作内存。FP32新模型不能仅按参数数目声称存储更小。 |
| 全链路计算 | 统计所有事件的表征成本、每窗Proposal及候选Refiner成本；门控拒绝事件也计入输入规模。 |
| 状态与缓存 | 输入计数、历史特征、缓存、峰值激活分别记录。双32×34×44 FP32状态约374 KiB，不是总内存。 |
| 实际时间 | 固定设备、线程、精度和输入；预热后至少3次完整回放，报告每百万事件耗时、P50/P95/P99和波动。 |
| 能量与硬件 | MAC/访存是代理；GPU设备能量不是整机或KV260能量。未测项目标“未测”。 |

## 你亲手完成的性能测量

1. 从逐层尺寸手算H2和学生的权重与计算量，再与程序统计交叉检查；新增特征维度或bias后重新计算。
2. 分项分析表征、搬运、Proposal、候选整理、Refiner和回填；最终结论用完整外层计时，评分/磁盘读取单列。GPU异步执行必须正确同步。
3. 在同一软件后端建立H2与候选速度比较；若一个用NumPy另一个用GPU，只能报告系统组合差异，不能归因于网络结构。
4. 优化缓存、预取和重复特征计算时验证输出等价；不改变数据顺序、精度或样本选择后再称为等价优化。

在线分支另报告等待+排队+计算+传输，以及积压与超时比例。P95计算小于25 ms、事件端到端小于50 ms仅作为后续在线目标，不限制本轮精度主线。

结构目标：至少减1层、权重目标减少20%；效率目标：全链路时间争取减少20%，精度损失不超过0.3点且仍超过H2。各目标分别验收，不能互相替代。
