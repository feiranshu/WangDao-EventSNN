# H2-S1 模型改进研究协作规则

## 适用范围与信息优先级

本文件适用于 `implementation/` 及全部子目录，是当前实现的协作和执行规则。

开始工作时按以下顺序阅读：

1. `AGENTS.md`：边界、验证、记录和协作规则。
2. `README.md`：当前结论、七步完成状态和停止点。
3. `README_SERVER.md`：服务器正式运行的唯一逐条命令来源。
4. `PLAN.md`：完整研究路线、历史设计和验收协议。

发生冲突时，以用户最新指令和当前实际文件为准；`README.md` 的当前状态优先于 `PLAN.md` 中标明为历史记录的内容。外部工程只可作为只读参考，不得成为本目录的隐式运行时依赖。

## 当前目标与状态

- 目标优先级固定为：识别准确性 > 模型复杂度。任何减层、蒸馏、量化或在线化都不能绕过准确性门槛。
- H2 是 ANN 基线，不能写成 SNN；旧 S1 是 SNN Proposal 加 ANN Refiner。软件推理、硬件仿真、综合结果和 FPGA 实测必须明确区分。
- 步骤1的10条 Train-dev 错误归因已经完成。步骤2至步骤4的代码和本地闭环已完成，正式训练等待服务器结果。
- 当前服务器顺序是先运行 A1/A2 seed42，再根据门槛决定补种子、A3/A3-null和学生模型。不得因为入口已经存在就把所有分支同时排队。
- 步骤5在线分支是条件分支，主精度结论稳定且确有在线需求前不启动正式训练。
- 步骤7的冻结和一次性 Validation/Test 入口已经实现，但当前没有运行任何受保护评测。
- 当前 H2 Proposal 阈值为0.51；H2-F事件阈值为0.28；H2-R在 Train-dev 的公平工作点为0.30。当前管线没有边界框 NMS，不得杜撰 NMS 阈值。

## 环境与运行规则

- 后续正式运行统一使用服务器已有的 Conda 环境 `evuav`，不创建项目内 `.venv`。本机同名环境不作为服务器执行依据。
- 所有命令从 `implementation/` 根目录执行。服务器完整命令和回传清单只维护在 `README_SERVER.md`。
- 新解压包必须使用新的空目录，不覆盖旧项目目录、训练结果或启动标记。
- 当前项目只注册源码，不主动更新服务器已有依赖：`python -m pip install -e . --no-deps --no-build-isolation`。
- 正式训练前必须记录环境信息并运行 `python -m pip check` 和全部82项单元测试；任何失败都先保存日志并停止正式训练。
- 本地只运行短测试、冒烟和不访问受保护数据的检查。本地结果不能写成服务器正式训练、GPU性能或 FPGA 实测。
- 预计耗时较长的训练、完整数据评测、综合或板级实验不得在本地代跑；把完整命令、输出位置和回传清单写入或核对 `README_SERVER.md` 后交由服务器执行。
- 不为排查方便创建第二套 Python 环境，不擅自升级服务器驱动、CUDA、PyTorch或其他依赖。若环境实际失败，再根据日志单独处理。

## 数据边界与实验纪律

- Train-main仅用于训练。
- Train-dev用于 checkpoint、阈值、早停、候选选择和消融判断。
- HW-calibration只用于定点、近似计算和硬件校准。
- Validation只允许在模型、阈值、位宽、近似规则和后处理全部冻结后运行一次。
- Test只允许在匹配的Validation完成后运行一次。不得根据Validation或Test返回结果修改模型或阈值后覆盖原结果。
- 开发阶段不得重新生成或改写 `data/index.json`，也不得以数据审计为名提前读取受保护角色。现有冻结索引是唯一依据。
- A*必须使用同一配方完成seed42/43/44。冻结门槛为：seed42相对H2-R至少提高0.5个百分点，三种子平均增益为正，至少两个种子为正。
- S*必须保持高于H2，且seed42相对A*的损失不超过0.3个百分点。S-R2只在S-R1准确性不足时启动。
- A3只有同时优于同维同参A3-null，才能把收益归因于历史信息。
- 所有候选使用相同阈值网格和Pd/Fa约束。单纯工作点变化不能写成网络结构收益。
- 一次实验只改变一个主要因素。训练损失只能用于过程监控和初选，最终结论以完整Train-dev端到端指标及逐序列证据为准。

## 性能与缓存

- 训练前检查数据读取、CPU表征和GPU等待是否构成瓶颈；优先采用不改变数学结果的向量化、共享不可变数据、后台预取和有界缓存。
- 性能优化不得改变数据划分、样本及顺序、随机数调用、batch边界、标签、数值精度、损失或参数更新。可能改变结果的改动必须作为独立实验。
- `results/runs/h2_candidate_cache_v2/` 是可再生候选缓存，不进入上传包或正式结果。
- `__pycache__`、`.pyc`、临时解压目录和本地环境目录不得进入上传包或长期结果。

## 结果与文档

- 有研究意义的训练、评测、量化、近似计算和发布运行应保存结构化JSON；普通文件检查、帮助命令和单元测试不单独创建研究结果。
- 正式结果放在 `results/`；训练过程、探索、冒烟、日志、预测和checkpoint放在 `results/runs/`。
- 新增正式结果的顶层字段统一使用 `schema_version`、`status`、`experiment_id`、`stage`、`data_role`、`primary_metrics`、`decision` 和 `conclusion`；训练历史保存在同一结果的 `history` 数组中。
- 不覆盖冻结权重、冻结清单或受保护评测结果。身份、哈希或内容不一致时创建新版本并明确记录原因。
- README只保留当前结论和入口；PLAN保留完整路线与有价值的历史；AGENTS只保留协作规则；服务器命令只维护在README_SERVER。不要新增零散状态文档。
- 修改实现、运行顺序、环境入口、结果门槛或当前状态后，同步更新受影响的文档。普通排查且结论未变化时不更新文档。
- 结论必须与证据等级一致：冒烟不能写成正式增益，Train-dev不能写成Validation/Test，CPU计时不能写成GPU或板级结果。
